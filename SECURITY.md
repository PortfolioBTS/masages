# Политика безопасности Nyxo

## Реализованная защита

1. **Content Security Policy (CSP)** — nonce-based, запрещает inline скрипты и стили.
2. **CSRF защита** — double-submit cookie pattern.
3. **Rate Limiting** — ограничение попыток входа, регистрации, смены пароля и API.
4. **Magic Bytes** — проверка содержимого загружаемых файлов.
5. **Параметризованные запросы** — защита от SQL-инъекций через pg.
6. **Сессии** — хранятся в PostgreSQL, httpOnly cookie.
7. **WebSocket авторизация** — проверка сессии перед join комнаты.
8. **Защищённая раздача файлов** — только авторизованным пользователям.

## Известные ограничения

- **Сквозное шифрование (E2EE) сейчас не подключено.** В репозитории есть
  отдельный, полностью реализованный Rust-сервис `e2ee-key-server`
  (X3DH-обмен ключами, one-time prekeys, подписи — см.
  `e2ee-key-server/README.md`), но ни `server.js`, ни клиентский код в
  `public/` пока ни разу к нему не обращаются. Текст сообщений сегодня
  хранится в PostgreSQL и передаётся между клиентом и сервером (включая
  Socket.IO) в открытом виде — так же, как в обычном мессенджере без E2EE.
  Наличие `e2ee-key-server` в проекте не означает, что переписка сейчас
  зашифрована end-to-end; это задел под будущую интеграцию, а не
  подключённая защита.

## Исправлено по итогам аудита (2026-08)

1. **`/uploads/:filename`** — теперь проверяется, что запрашивающий действительно участник чата/комнаты, к которой относится файл (не просто «залогинен ли кто-то вообще»).
2. **`CF-Connecting-IP`** — заголовку доверяем только если запрос физически пришёл с IP-адреса Cloudflare (см. `CF_IP_RANGES` в `.env.example`).
3. **Реакции** — на бэке добавлен allowlist из 5 разрешённых эмодзи; на фронте рендеринг обёрнут в `escapeHtml`.
4. **Тайминг-атака на `/api/login`** — `bcrypt.compare` теперь всегда выполняется (с фиктивным хэшем, если юзера нет), что убирает разницу во времени ответа.
5. **SSL до Postgres** — при заданном `DB_CA_CERT` используется `rejectUnauthorized: true` с закреплённым CA; без него — явно залогированный компромисс.
6. Правки и удаления сообщений (`PUT`/`DELETE /api/messages/:id`) теперь рассылаются по WebSocket остальным участникам комнаты.
7. Минимальная длина пароля увеличена с 6 до 8 символов (ближе к NIST 800-63B).
8. Проверка magic bytes при загрузке файла теперь fail-closed: любая ошибка проверки = отказ в загрузке, а не пропуск файла.

## Дополнительно найдено и исправлено при функциональном тестировании (вне исходного аудита)

- `POST /api/messages/file` — multer записывает файл на диск ДО проверок в хендлере (401/400/404), из-за чего каждая отклонённая/поддельная попытка загрузки оставляла файл-сироту на диске. Добавлена очистка на всех ранних `return`.
- `DELETE /api/chats/:chatId` полностью падал с нарушением внешнего ключа при удалении/выходе из комнатного (много-пользовательского) чата — то есть базовая функция "удалить чат" была нерабочей для этого типа чатов. Причина — рассинхронизация порядка удаления строк с ограничениями FK (`chats.room_id → rooms.id`, `messages.chat_id → chats.id`, `reactions.message_id → messages.id`). Исправлено: пересмотрен порядок операций в хендлере + миграция FK (`ON DELETE SET NULL` для `messages.chat_id`/`messages.reply_to_id`, `ON DELETE CASCADE` для `chats.room_id`, `reactions.message_id`, `messages.room_id`, `unread.chat_id`, `room_participants.room_id`). История комнаты для остальных участников не теряется — сообщения остаются видны по `room_id`, даже если автор уже вышел.
