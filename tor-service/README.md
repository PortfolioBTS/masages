# tor-service — onion-адрес для Nyxo

Отдельный сервис Railway, который публикует Nyxo в сети Tor как v3 onion-сервис.

```
Tor Browser ──(сеть Tor, сквозное шифрование)──> tor ──> socat 127.0.0.1:8080
                                                            │
                               private network Railway      ▼
                                         <app>.railway.internal:<ONION_PORT>  (приложение Nyxo)
```

- **tor** держит ключ onion-адреса и принимает соединения из сети Tor
  (`HiddenServicePort 80 127.0.0.1:8080`).
- **socat** пробрасывает каждое соединение в приложение. Он нужен потому, что
  `HiddenServicePort` принимает только IP, а IP приложения в private network
  Railway может смениться при редеплое. socat резолвит `TARGET_HOST` заново
  на каждое соединение.
- Ключи и состояние tor лежат на volume `/var/lib/tor` и переживают редеплой.
  Без volume при каждом деплое будет новый адрес.
- tor работает от `debian-tor`, socat — от `nobody`. Root нужен только
  entrypoint'у в первые миллисекунды, чтобы выставить права на volume: Railway
  монтирует его от root. После этого привилегии сбрасываются (`setpriv`,
  `no_new_privs`).

## Что даёт onion и чего не даёт

Сервер Nyxo и так публичен: у него есть домен на Railway, и его местоположение
известно. Поэтому onion здесь защищает **клиента**, а не сервер.

Что даёт:

- **Скрывает клиента.** Сервер, Railway и Cloudflare не видят IP и
  местоположение пользователя. Его провайдер видит только, что он пользуется Tor.
- **Соединение сквозное, внутри Tor.** Нет выходного узла, который видел бы, куда
  идёт трафик, и нет Cloudflare, который при обычном входе расшифровывает TLS и
  видит HTTP-запросы (содержимое E2EE-сообщений он не видит, но метаданные видит).
- **Сервер аутентифицируется самим адресом.** Адрес — это открытый ключ сервиса,
  а удостоверяющие центры и DNS не участвуют. Подменить сайт, не имея ключа, нельзя.
- **Обходит блокировки** домена и Cloudflare.
- Регистрация через onion не упирается в лимит по IP: вместо него работает
  proof-of-work (`lib/pow.js`, `public/pow-worker.js`).

Чего не даёт:

- **Не скрывает сервер.** Railway, его местоположение и оператор известны.
- **Не защищает от самого сервера.** Всё, что приложение знает о пользователе
  (аккаунт, время активности, собеседники), оно знает и через onion. Содержимое
  защищает только E2EE.
- Участок socat → приложение идёт по private network Railway без TLS. Сама сеть
  шифруется Railway (WireGuard), но оператор платформы имеет доступ к контейнерам
  и к volume с ключом onion-адреса.
- Все onion-пользователи приходят в приложение с одного адреса (контейнер
  tor-service). Поэтому для onion-соединений приложение не считает лимиты по IP,
  а считает их по аккаунту (вход, API, сокеты), регистрацию сдерживает
  proof-of-work.

## Деплой на Railway

1. **Новый сервис из этого же репозитория.** New → GitHub Repo → тот же репозиторий.
   В Settings → Source укажите **Root Directory** `/tor-service`. Railway найдёт
   `Dockerfile` сам.
2. **Volume.** Добавьте к сервису volume с mount path **`/var/lib/tor`**.
   Реплика должна быть одна. Два tor с одним ключом конфликтуют, а volume и так
   не даст запустить вторую.
3. **Переменные tor-service:**
   - `TARGET_HOST` — приватный адрес приложения: `<имя-сервиса>.railway.internal`,
     или ссылкой `${{<имя-сервиса>.RAILWAY_PRIVATE_DOMAIN}}`;
   - `TARGET_PORT` — внутренний onion-порт приложения (его `ONION_PORT`, не `PORT`).
4. **Переменные приложения:**
   - `HOST=::`. Private network в части окружений Railway работает только по IPv6,
     а `::` в Node слушает и IPv6, и IPv4, так что публичный доступ не пострадает;
   - `ONION_PORT` — отдельный внутренний порт для tor-service, например `3001`
     (то же значение — в `TARGET_PORT`). Он должен отличаться от `PORT`, и его
     **нельзя публиковать наружу**: публичный домен Railway ведёт только на `PORT`.
     Приложение считает onion-запросом всё, что пришло на `ONION_PORT`, —
     по порту соединения, а не по заголовкам, которые клиент может подделать.
5. **Публичный домен tor-service не нужен.** Не генерируйте его: сервису не нужны
   входящие соединения, tor сам подключается к сети Tor.
6. **Deploy.** В логах tor-service появится строка
   `[tor-service] onion-адрес: <56 символов>.onion`. Первая публикация
   дескриптора занимает до пары минут.
7. **Скопируйте адрес в переменную `ONION_ADDRESS` приложения** (только хост,
   без `http://`) и передеплойте приложение. После этого приложение:
   - отмечает запросы, пришедшие на `ONION_PORT` (`req.isOnion`), и не доверяет
     присланным в них заголовкам `X-Forwarded-*`;
   - отдаёт на страницах открытого сайта заголовок `Onion-Location`. Tor Browser
     показывает по нему кнопку «.onion доступен». Заголовок работает только для
     страниц по HTTPS, а домен Railway — HTTPS.
8. **Проверка:** откройте `http://<адрес>.onion` в Tor Browser и войдите.
   Tor Browser считает `.onion` защищённым контекстом, поэтому Secure-кука сессии
   работает и по `http://`. В обычном браузере с Tor в качестве прокси вход может
   не работать.

При редеплое tor-service onion-адрес недоступен несколько секунд, пока новый
контейнер поднимает volume и публикует дескриптор. Приложение при этом
работает как обычно.

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `TARGET_HOST` | да | DNS-имя (или IPv4) приложения в private network, например `nyxo.railway.internal` |
| `TARGET_PORT` | да | внутренний onion-порт приложения (его `ONION_PORT`) |
| `TARGET_IP_FAMILY` | нет | `4` или `6` — принудительно IPv4/IPv6 при подключении к приложению. По умолчанию выбор по DNS |
| `TOR_SINGLE_ONION` | нет | `true` — режим Single Onion (см. ниже). По умолчанию `false` |
| `MAX_CONNECTIONS` | нет | максимум одновременных соединений через socat (по процессу на соединение), по умолчанию `512` |

Кроме того, в `torrc` зашито `HiddenServiceMaxStreams 64`: не больше
64 одновременных соединений на один circuit (одного клиента). Circuit,
превысивший лимит, закрывается.

## Single Onion Service (по умолчанию выключен)

Обычный onion-сервис прячет и клиента, и сервер: до точки встречи строятся
по 3 узла с каждой стороны. В режиме Single Onion (`TOR_SINGLE_ONION=true`,
то есть `HiddenServiceNonAnonymousMode 1` + `HiddenServiceSingleHopMode 1`)
сервис подключается к точкам знакомства и встречи напрямую. Выходит меньше
узлов на пути и заметно ниже задержка.

Почему это разумный компромисс именно здесь: местоположение сервера и так
известно (публичный сайт на Railway), так что сокрытие его в Tor почти ничего не
добавляет. **Клиент остаётся анонимным**, его половина пути не меняется.

Цена:

- IP контейнера tor-service видят узлы-точки знакомства и встречи. Отличить Single
  Onion от обычного onion-сервиса можно статистически.
- Режим необратим для ключа. По документации tor, каталог, однажды
  использованный в SingleHopMode, нельзя снова использовать для обычного
  onion-сервиса. Поэтому у Single Onion **свой каталог и свой адрес**
  (`/var/lib/tor/nyxo-single`), и при переключении `TOR_SINGLE_ONION` в любую
  сторону меняется onion-адрес. Не забудьте обновить `ONION_ADDRESS` приложения.
  Старый ключ остаётся на volume, и при возврате в прежний режим вернётся прежний адрес.

## Резервное копирование ключей

Onion-адрес — это ключ `hs_ed25519_secret_key` в каталоге сервиса
(`/var/lib/tor/nyxo/`, для Single Onion — `/var/lib/tor/nyxo-single/`).

- **Потеря ключа** означает потерю адреса: придётся раздавать пользователям новый.
- **Утечка ключа** означает, что кто угодно сможет выдавать себя за ваш onion-сервис.
  Храните резервную копию так же бережно, как `SESSION_SECRET`: в менеджере
  паролей или в зашифрованном офлайн-хранилище. Не кладите её в git и в
  переменные окружения.

Как снять копию: включите бэкапы volume в Railway или вручную выгрузите
каталог сервиса целиком (ключи и `hostname`) через Railway CLI
(`railway ssh` в сервис tor-service):

```sh
tar -C /var/lib/tor -czf - nyxo | base64
```

Как восстановить: распакуйте архив обратно на volume
(`base64 -d | tar -C /var/lib/tor -xzf -`) и перезапустите сервис. Владельца
и права (`debian-tor`, каталоги `700`, файлы без доступа для группы и
остальных) entrypoint выставляет сам при каждом старте.

## Ограничения

- От флуда самого onion-сервиса защищают `HiddenServiceMaxStreams` и лимиты
  приложения по аккаунту. Встроенную PoW-защиту tor
  (`HiddenServicePoWDefensesEnabled`, tor ≥ 0.4.8) можно добавить в `torrc`,
  если используемая сборка tor её поддерживает.
- tor берётся из `bookworm-backports` (а если его там нет, то из `bookworm`).
  Нужна другая ветка — замените установку в `Dockerfile` на официальный
  репозиторий `deb.torproject.org` с проверкой ключа.
